一、核心想法（3 分钟）

猜 1-100 之间的数（跟 W05 一样）。两种玩法：

玩法 步数
笨办法：从 1 开始一个个猜 最坏 100 步
聪明办法：每次猜中间 最坏 7 步

每次猜中间，砍掉一半——这就是二分查找（binary search）。

想象一把有刻度的尺子，指针指在中间。如果目标在指针左，砍掉右边；如果在右，砍掉左边。重复，每次砍一半。

三、为什么偏偏是 7（3 分钟）

每问一次砍一半：100 → 50 → 25 → 12 → 6 → 3 → 1。

反过来想：砍 7 次"只剩 1 格"，需要一开始有多少格？在 Shell 里验证：

>>> 2 ** 7
128

128 ≥ 100，所以 7 次够。通用公式：N 格，最多要 ⌈log₂(N)⌉ 问。

五、二分的两个前提（3 分钟）

"砍一半"需要两个前提：

  1. 有序——必须按某种顺序排好（数字大小、字母顺序）
  2. 能跳中间——必须能直接看第 N 个（数组支持，链表不支持）

如果无序，只能挨个问"是 X 吗？"——那就是顺序查找（linear search），W07 会学。

六、深入了解：二分查找的历史八卦（3 分钟）

二分查找是最古老的算法之一——第一个版本 1946 年发表——但第一个真正没 bug 的版本要到 16 年后才出现。

为什么？陷阱藏在边界里：

  • 循环条件 while low <= high 还是 while low < high？
  • 更新 high = mid 还是 high = mid - 1？
  • 选错就死循环或漏掉元素

多测边界：空列表、单元素、目标在第一个、目标在最后一个、目标不存在。

隐藏 bug：mid = (low + high) // 2 看起来天真，但 Java/C 里 low + high 超过 2³¹ 会回绕成负数。Python 原生支持大整数，没事。安全写法：mid = low + (high - low) // 2。

2006 年 Google 工程师发现 Java 标准库的二分查找有 bug——潜伏了快十年。所以第一次写错完全正常。

二、四种模式速查（5 分钟）

模式 Big O 数据翻倍，时间变成 例子
常数 O(1) 不变 字典查找（W11）
对数 O(log n) +1 步 二分查找（今天）
线性 O(n) ×2 顺序查找（W07）

关键：翻倍测试——把 N 从 100 改到 200，时间变成：

  • O(1)：不变（还是 1 步）
  • O(log n)：7 → 8（只 +1）
  • O(n)：100 → 200（×2）
  • O(n²)：10000 → 40000（×4）

三、为什么二分查找是 O(log n)（3 分钟）

每步砍一半：100 → 50 → 25 → 12 → 6 → 3 → 1。要的步数 = 砍的次数 = log₂(100) ≈ 7。

数据翻倍（100 → 200），步数变 log₂(200) ≈ 8——只 +1 步。

📖 图 2.1：每次砍一半。像把一摞 100 张牌每次分成两半，7 次后只剩 1 张。

通用公式：N 格，最多要 ⌈log₂(N)⌉ 步 = O(log n)。

四、对比：顺序查找 vs 二分查找（5 分钟）

想象一个 10000 格的问题：

算法 10000 格要几步 翻倍测试（10000 → 20000）
顺序查找（挨个问） 10000 步 ×2 → 20000 步
二分查找（砍一半） 14 步 +1 → 15 步

顺序查找是跟 N 成正比地涨：10000 → 20000 → 40000 → ... 二分查找是对数地涨：10000 → 20000 → 40000 → ...

  • 10000 要 14 步
  • 100 万要 20 步
  • 10 亿要 30 步

10 亿格：顺序 = 10 亿步（要好几年），二分 = 30 步（瞬间）。

📖 图 2.2：随着 N 增长，二分（蓝线）vs 顺序（红线）差距像悬崖。N=10 亿时，顺序要走 10⁹ 步（你重孙子辈），二分走 30 步（眨眼）。

五、深入了解：Big O 的由来（3 分钟）

Big O 是德国数学家 Paul Bachmann 在 1894 年发明的，符号是 "O"——德语 "Ordnung"（秩序）的首字母。原意是"量级的秩序"，不是英语 "Order"（订单）。

常见误读：

  • "O(n²) 总是比 O(n) 慢"——错。N=10 时，O(n²) = 100 步，O(n) = 10 步，差 10 倍——可能 O(n²) + 常数小也快
  • "O(log n) 永远快"——错。N=2 时，O(log n) = 1 步，O(1) = 1 步，没差
  • 永远先量，再下结论——这是 Big O 的精神

六、何时用：Big O 选择算法（3 分钟）

场景 选什么 为什么
N < 100 顺序查找 / 简单排序 简单，够快
N < 10000 二分查找 简单又快
N > 100000 永远用二分/哈希 否则慢得离谱
训练 AI 哈希表 + 二分 数据大

AI 工程师第一课学 Big O——选错算法 = 性能差 10-100 倍。

def guess_number(low, high):
    '''Each step cuts in half, guess the middle.'''
    mid = (low + high) // 2
    print(f'I guess: {mid}')
    return mid

def update_range(low, high, mid, answer):
    '''Narrow range based on computer's answer -- W05 pattern.'''
    if answer == 'smaller':
        return mid + 1, high      # answer < mid, eliminate mid and below
    elif answer == 'bigger':
        return low, mid - 1       # answer > mid, eliminate mid and above
    else:  # hit
        return mid, mid

def main():
    low, high = 1, 100
    while low <= high:
        mid = guess_number(low, high)
        answer = input('bigger / smaller / hit? ').strip()
        if answer == 'hit':
            break
        low, high = update_range(low, high, mid, answer)
    print('Found it!')

main()

四、为什么"砍中间"？（3 分钟）

W06-S1 说砍一半——但砍哪儿？三种选择：

策略 例子 速度
永远砍第一个 low 不动，high 移动 顺序查找（W07 会对比）
永远砍中间 mid = (low + high) // 2 二分查找（今天）
随机砍 没规律 不可预期

中间 = 平衡。砍完两边差不多大。最坏情况 = 平衡树深度 = log₂(N)。

📖 图 3.1：中间 = 平衡 = 砍完两边差不多大。这是二分为什么"快"的核心。

五、// 整除：要中间但不要小数（2 分钟）

(low + high) // 2：

  • low=1, high=100：(1+100) // 2 = 50
  • low=50, high=100：(50+100) // 2 = 75

为什么用 // 不用 /？Python 的 / 给出小数：101/2 = 50.5。做列表下标会报错。// 永远整数：101//2 = 50。

六、深入了解：二分查找为什么老出错（3 分钟）

Donald Knuth（《计算机程序设计艺术》作者）说过："二分查找看似简单，实则陷阱重重"。

常见 bug：

  1. while low < high（漏 =）—— 漏掉 low == high 的情况
  2. high = mid（漏 -1）—— 多查一次
  3. mid = (low + high) / 2（用 /）—— 整数被算成小数

多测边界：

  • 空列表（len = 0）
  • 单元素（len = 1）
  • 目标在第一个
  • 目标在最后一个
  • 目标不存在

2006 年 Java 标准库的二分查找 bug 潜伏了快十年。你的代码也几乎肯定会有 bug——写完多测。

七、何时用：二分查找的 4 个变种（3 分钟）

场景 变种 代码差异
找目标 标准二分 找到就 return
找第一次出现 下界 不停往左缩
找最后一次出现 上界 不停往右缩
找"插入位置" 二分插入 找不到就返回 mid

W06-S4 的词典查找就是标准版。W06-S5 的"选对算法"会用上界。

三、二分查找代码（5 分钟）

def binary_search(word_list, target):
    '''Cut in half each time. word_list must be sorted.'''
    low = 0
    high = len(word_list) - 1
    while low <= high:
        mid = (low + high) // 2
        if word_list[mid] == target:
            return mid
        elif word_list[mid] < target:
            low = mid + 1   # target is in the right half
        else:
            high = mid - 1  # target is in the left half
    return -1

words = ['apple', 'banana', 'cherry', 'date', 'elderberry', 'fig', 'grape']
print(binary_search(words, 'cherry'))   # 2
print(binary_search(words, 'kiwi'))      # -1

最坏：10000 词列表。步数 = log₂(10000) ≈ 14。

import time

def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1

def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

def in_list(arr, target):
    '''Python's built-in `in` operator.'''
    return target in arr

def set_lookup(s, target):
    '''Convert to set, then lookup.'''
    return target in s

# Make 10000-element sorted list
N = 10000
sorted_arr = list(range(N))   # 0, 1, 2, ..., 9999
s = set(sorted_arr)            # set version
# Worst case (last element)
target = N - 1

# Time each
for name, fn in [('Linear', linear_search), ('Binary', binary_search),
                 ('in_list', in_list), ('set_lookup', set_lookup)]:
    start = time.time()
    result = fn(sorted_arr if 'set' not in name else s, target)
    elapsed = time.time() - start
    print(f'{name:10s}: {elapsed:.6f}s  found={result}')

👀 C++ 认脸时刻（1 分钟 · 只看不敲）

#include <iostream>
#include <vector>
int main() {
    std::vector<int> arr = {0, 1, 2, 3, 4, 5};
    int target = 3;
    // C++23 has std::find (linear); binary_search returns bool
    bool found = std::binary_search(arr.begin(), arr.end(), target);
    auto it = std::lower_bound(arr.begin(), arr.end(), target);
    int index = it - arr.begin();   // 3
    std::cout << "found=" << found << " index=" << index << std::endl;
}

三个认脸：

  • std::lower_bound 返回第一个 ≥ target 的迭代器
  • it - arr.begin() = 下标（指针算术）
  • 跟 Python 的 bisect.bisect_left(arr, target) 一个意思
