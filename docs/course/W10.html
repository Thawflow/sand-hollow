W10-S1 · def 初见：为什么要打包

每日节奏（v1.9）： 本篇纯阅读 ≈10 分钟，读完做当天作业 ≈10 分钟，总共 ≤25 分钟 不需要 Thonny——正文一个字都不用敲，作业时间才开编辑器 难度：⭐⭐ · 本篇是原 W08-L01 的前半（函数概念 + def 的样子）

一、你早就在用函数了（3 分钟）

W07 的 battle(player, wolf)、每天的 print(...)、input(...)——全是函数：一段有名字的代码，可以反复调用。区别只是：print 是别人写好的，这周开始写你自己的。

为什么非要打包？三个理由：

  • 不重复：同一段代码不抄 10 遍
  • 改一处：函数改好，10 个调用点全部生效
  • 读得懂：battle(player, wolf) 一行，胜过 30 行战斗代码摊在眼前

二、def 的样子（4 分钟）

def greet(name):
    print(f"Hello, {name}!")
    print("Welcome to Python.")

greet("Alice")
greet("Bob")

四件套拆解：

  • def：定义（define）的缩写——「我要造积木了」
  • greet：函数名，自己起，最好用动词
  • (name)：参数，调用时传进来的数据（明天专门学）
  • : + 缩进：冒号下面缩进 4 格的，都是函数体

三、定义 ≠ 执行（3 分钟）

最反直觉的一点：def 那一刻什么都不执行，只是把函数记进了 Python 的名册。真正执行的是调用——顶格写的 greet("Alice")：

def say_hello():
    print("Hello!")

say_hello
say_hello()

say_hello（没括号）只是指着这块积木，不执行、不报错；say_hello()（带括号）才是「执行它」。忘写括号 = 新手第一大坑：程序安静跑完，一行 Hello 都没有。

今日口诀： def 造积木，调用才出发；括号不写，万物静默。

W10-S2 · 参数：积木的凹槽

每日节奏（v1.9）： 本篇纯阅读 ≈10 分钟，读完做当天作业 ≈10 分钟，总共 ≤25 分钟 不需要 Thonny——正文一个字都不用敲，作业时间才开编辑器 难度：⭐⭐ · 本篇是原 W08-L02 的前半（位置参数 + 多参数）

一、凹槽：函数接住外面的数据（3 分钟）

调用时塞值进去，函数定义时挖槽接住——参数让一段代码变通用：

def introduce(name, age, hobby):
    print(f"I'm {name}, {age} years old.")
    print(f"I like {hobby}.")

introduce("Alice", 12, "drawing")
introduce("Bob", 11, "coding")

同一个函数，两份数据，两种输出。塞进去的叫实参（实际的值），接住它们的凹槽叫形参（形式上的名字）——新手期记不住术语没关系，记住「塞值 → 凹槽」就行。

二、按位置对应：第一坑（3 分钟）

introduce("Alice", 12, "drawing") → name="Alice"、age=12、hobby="drawing"。按位置一一对应——所以顺序错了语义就错：

introduce(12, "Alice", "drawing")

不报错！但输出变成「I'm 12, Alice years old」——程序很听话，错的是你。参数错位是「安静的 bug」，比报错难抓。

三、按名字传：关键字参数（3 分钟）

不想记顺序？用名字指定，顺序随意：

introduce(hobby="coding", name="Bob", age=11)

混用规则只有一条：没名字的（位置参数）必须在前。

introduce(name="Alice", 12, "drawing")

这行是 SyntaxError——关键字参数后面不能再跟裸的位置参数。

四、数量必须对上：第二坑（2 分钟）

函数挖两个槽，你塞三个值（或只塞一个）→ TypeError: introduce() takes 3 positional arguments but 2 were given。报错其实很友善：槽几个、给了几个，写得明明白白。见到 TypeError 先数参数。

今日口诀： 塞值进凹槽，位置一一咬；按名传也行，名字不能少。

W10-S3 · 默认值：不传就用默认

每日节奏（v1.9）： 本篇纯阅读 ≈10 分钟，读完做当天作业 ≈10 分钟，总共 ≤25 分钟 不需要 Thonny——正文一个字都不用敲，作业时间才开编辑器 难度：⭐⭐ · 本篇是原 W08-L02 的后半（默认值参数）

一、给凹槽预设一个值（3 分钟）

参数可以带默认值——调用时不传，就自动用默认：

def greet(name, greeting="Hello"):
    print(f"{greeting}, {name}!")

greet("Alice")
greet("Alice", "Hi")
greet("Bob", greeting="Hey")

三次调用：第一次 greeting 用默认 Hello；第二次位置传 Hi；第三次按名传 Hey。一个函数，三种口味——常用值不用每次写。

二、咖啡机实战（4 分钟）

def make_coffee(size="medium", sugar=0):
    print(f"Coffee: {size}, sugar: {sugar} spoons")

make_coffee()
make_coffee("large")
make_coffee(sugar=2)
make_coffee("small", sugar=1)

读懂四种点单方式：全默认 / 只传第一个 / 只传第二个（必须带名字）/ 混着传。只改后面参数、跳过前面参数时，必须用名字——make_coffee(sugar=2) 不能写成 make_coffee(2)（那会把 2 当成 size）。

三、默认值放最后（2 分钟）

规矩：有默认值的参数必须排在没默认值的后面。想想为什么——按位置传参时 Python 从左往右填槽，如果中间的槽有默认值，后面的必传参数就永远收不到值了。

def greet(greeting="Hello", name):

SyntaxError。改成 def greet(name, greeting="Hello") 才合法。

print_scores([85, 92, 78], label="Math Test", show_total=False)

每日节奏（v1.9）： 本篇纯阅读 ≈11 分钟，读完做当天作业 ≈10 分钟，总共 ≤25 分钟 不需要 Thonny——正文一个字都不用敲，作业时间才开编辑器 难度：⭐⭐ · 本篇是原 W08-L03 的前半（return + 多个 return）

一、函数不只干活，还要交货（3 分钟）

前几天的函数都是 print 完就走。更多时候函数要返回一个值给调用方用：

  • input(...) → 返回用户输入
  • random.randint(1, 100) → 返回随机数
  • W07 的 battle(...) → 返回 True/False（你早就用过 return 了）

二、return 的样子（4 分钟）

def add(a, b):
    return a + b

result = add(3, 5)
print(result)
print(add(10, 20))

关键认知：add(3, 5) 本身就是一个值（8）。可以接住存变量、可以直接丢给 print、还可以继续参与计算——add(3, 5) * 2 就是 16。

三、return vs print：新手分水岭（4 分钟）

print return
给谁 显示给人看 交给程序用
能赋值吗 不能（得到 None） 能
能参与计算吗 不能 能 
def add_print(a, b):
    print(a + b)

def add_return(a, b):
    return a + b

double = add_return(3, 5) * 2

上面 double 能算出 16；换成 add_print，它「打印了 8」但交出来的东西是 None——None 乘 2 直接 TypeError。原则：要接住就用 return，纯展示才用 print。

四、多个 return：见好就收（3 分钟）

def find_biggest(nums):
    if not nums:
        return None
    biggest = nums[0]
    for n in nums:
        if n > biggest:
            biggest = n
    return biggest

print(find_biggest([3, 7, 2, 9, 4]))
print(find_biggest([]))
  • if not nums: return None——空列表提前撤退（None = Python 的「无」）
  • 第一个碰到的 return 立刻执行，后面的代码不再跑
  • 一个函数可以写多个 return，各管一条出口——跟 W07-S5「出口清点」一个思路

今日口诀： return 交货，print 展示；碰谁谁走，货能再算。

        return False
    player["inventory"].remove(item_name)
    print(f"Used {item_name}!")
    return True

if use_item(player, "herb"):
    print("Healing done!")
else:
    print("No herb left")

调用方拿到 True/False，就能接着写 if——函数之间用 return 递话，主循环只管提问和分支，逻辑全住进函数里。

二、提前退出：return 是传送门（3 分钟）

def divide(a, b):
    if b == 0:
        print("Cannot divide by zero")
        return None
    return a / b

return None 一执行，函数立刻结束，后面一行都不跑——像传送门，碰到就回城。这就是「提前退出」：先处理异常（除零），正常逻辑再往下写，主路径不缩进、读着清爽。

改造 4：抽 save_game / load_game（进阶）

import json

def save_game(player, room):
    data = {"player": player, "room": room}
    with open("save.json", "w") as f:
        json.dump(data, f)
    print("Game saved!")

def load_game():
    with open("save.json") as f:
        data = json.load(f)
    print("Game loaded!")
    return data["player"], data["room"]

json.dump / json.load 是 Python 自带的「对象 ↔ 文件」转换。重点不是 JSON 本身，是 use 函数 + 文件读写 + try-except 错误处理。
