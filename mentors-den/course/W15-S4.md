## 一、概念：规则也是数据（3 分钟）

昨天的判定长串（三个 or 的 elif）能跑，但——**游戏规则本身写成了一堆 if，改一条规则要翻半天代码**。

换思路：石头剪刀布的规则是一张「谁克谁」对照表——**对照表 = 字典**（W10 全程都在练这个）。

```python
beats = {
    "rock": "scissors",
    "scissors": "paper",
    "paper": "rock",
}
```

读法：键**克**值——rock 克 scissors、scissors 克 paper、paper 克 rock。规则装进字典，判定就变成查表。

## 二、一行撂倒长判定（4 分钟）

```python
if player == computer:
    result = "tie"
elif beats[player] == computer:
    result = "win"
else:
    result = "lose"
```

**beats[player] 存的是 player 能打败的对手**——所以「beats[player] == computer」成立时，computer 正好是 player 的手下败将，player 赢。

三行读完整个逻辑：先排平局、再查表判赢、剩下判负——和昨天那串 or 的**结果一模一样**，但读起来像一句话。这就是「重构」：**功能不变，代码换更顺的写法**。

## 三、前提：输入必须合法（2 分钟）

查表前有个前提——`beats[player]` 里的 player 必须是三个键之一。玩家手滑输入 "rockkk" 会怎样？`KeyError` 摔门（W10-S2 的老坑）。

昨天作业已经练过安检门，今天把它焊在查表**前面**：

```python
if player not in choices:
    print("Invalid choice!")
    continue
```

continue = 跳过这局直接进下一局（W04/W05 见过）。**先安检、后查表**，永远。

## 四、emoji 输出（2 分钟）

给三种拳配上 emoji 字典，输出瞬间有画面：

```python
emojis = {
    "rock": "\U0001FAA8",
    "paper": "\U0001F4C4",
    "scissors": "\u2702\uFE0F",
}

print(f"You: {emojis[player]} vs Computer: {emojis[computer]}")
```

`\U0001FAA8` 这种是 emoji 的**转义写法**（Unicode 编号）——比直接粘 emoji 进代码稳，不会被编辑器悄悄换成别的字符。

**今日口诀：** 规则进字典，判定变查表；查表先安检，输出配 emoji。

## 👀 C++ 认脸时刻（1 分钟 · 只看不敲）

C++ 的对应写法：

```cpp
#include <iostream>
#include <map>
#include <string>
int main() {
    std::map<std::string, std::string> beats = {
        {"rock", "scissors"},
        {"paper", "rock"},
        {"scissors", "paper"}
    };
    std::cout << beats["rock"] << std::endl;
    return 0;
}
```

三个认脸：

1. C++ 嵌套初始化 map
2. `beats["rock"]` 查表
3. Python `beats = {"rock": "scissors"}`
