## 一、真问题：10000 词词典（3 分钟）

想象一本 10000 词的英文词典，按字母顺序排好。查 "warrior"。

两种方法：
- **顺序查找**：逐页翻——最坏 10000 次
- **二分查找**：翻到中间页，决定左还是右，重复——最坏 14 次

今天：两种都写，跑起来量时间，亲眼看 Big O。

## 二、顺序查找代码（5 分钟）

```python
def linear_search(word_list, target):
    '''Page through until found or done.'''
    for i, word in enumerate(word_list):
        if word == target:
            return i
    return -1

# Sorted word list (small sample)
words = ['apple', 'banana', 'cherry', 'date', 'elderberry', 'fig', 'grape']
print(linear_search(words, 'cherry'))   # 2
print(linear_search(words, 'kiwi'))      # -1
```

最坏：目标是最后一个单词或不在列表里。步数 = N（10000）。

## 三、二分查找代码（5 分钟）

```python
def binary_search(word_list, target):
    '''Cut in half each time. word_list must be sorted.'''
    low = 0
    high = len(word_list) - 1
    while low <= high:
        mid = (low + high) // 2
        if word_list[mid] == target:
            return mid
        elif word_list[mid] < target:
            low = mid + 1   # target is in the right half
        else:
            high = mid - 1  # target is in the left half
    return -1

words = ['apple', 'banana', 'cherry', 'date', 'elderberry', 'fig', 'grape']
print(binary_search(words, 'cherry'))   # 2
print(binary_search(words, 'kiwi'))      # -1
```

最坏：10000 词列表。步数 = log₂(10000) ≈ 14。

## 四、用 time 模块量时间（5 分钟）

```python
import time

# Make a 10000-word sorted list (simplified: word00000 ... word09999)
words = [f'word{i:05d}' for i in range(10000)]

# Worst case: search for last word
target = 'word09999'

start = time.time()
linear_search(words, target)
linear_time = time.time() - start

start = time.time()
binary_search(words, target)
binary_time = time.time() - start

print(f'Linear: {linear_time:.4f}s')
print(f'Binary: {binary_time:.4f}s')
print(f'Binary is {linear_time / binary_time:.0f}x faster than linear')
```

跑一下。看差距。在 10000 词上二分查找可能比顺序查找快 100-1000 倍。

## 五、示例演算：找 "cherry"（3 分钟）

在 `['apple', 'banana', 'cherry', 'date', 'elderberry', 'fig', 'grape']` 里找 "cherry"。

| 步骤 | low | high | mid | word_list[mid] | 反馈 |
|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | date | date > cherry，往左 |
| 2 | 0 | 2 | 1 | banana | banana < cherry，往右 |
| 3 | 2 | 2 | 2 | cherry | 命中！返回 2 |

## 六、深入了解：为什么 AI 离不开搜索（3 分钟）

**AI 系统的核心 = 搜索 + 优化**：
- **推荐系统**：搜"和你像的人"——把 1 亿用户里跟你行为最像的找出来
- **搜索引擎**：搜几十亿网页——你输入"算法"，0.1 秒返回几百万结果
- **聊天机器人**：搜"最合适的回答"——在 1 万亿 token 知识库找相关段

**加速招**：
- **预排序**：排好序的列表能二分
- **索引**：数据库给字段建索引（B 树、红黑树）
- **缓存**：算过的存起来（memcached、Redis）
- **向量搜索**：把文字变成数字"指纹"，搜指纹相近的（FAISS、Pinecone）

**2024-2026 AI 实验室最卷的方向就是搜索算法**——ChatGPT 用的"向量数据库"就是搜索算法的超级加强版。

## 七、何时用：二分 vs 顺序 vs 哈希（3 分钟）

| 场景 | 选什么 | 为什么 |
|---|---|---|
| 排好序的列表 | 二分 | O(log n) |
| 没排好序的列表 | 顺序 | 排序代价 > 搜索代价 |
| 反复查同一份数据 | **哈希表**（Python dict） | O(1) |
| 一次性查 | 顺序 | 简单 |

**AI 工程师选错 = 慢 100 倍**。先排序/建索引，再二分/哈希。
