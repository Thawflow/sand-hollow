## 一、四种算法模式速查表（5 分钟）

| 模式 | Big O | 例子 | 何时用 |
|---|---|---|---|
| 常数 | O(1) | 字典查找（W11） | 直接访问 |
| 对数 | O(log n) | **二分查找（今天）** | 排好序的数据 |
| 线性 | O(n) | 顺序查找 | 没排好序、N 小 |
| 平方 | O(n²) | 冒泡排序 | 只 N 小 |

**经验法则**：
- N < 100：随便选，挑最简单的
- N < 10000：顺序勉强 OK，二分更好
- N > 100000：**永远**用二分查找（或哈希表）

## 二、先排序，再搜索——AI 最常用的模式（5 分钟）

现实 AI 几乎都这么干：
1. **排序**数据一次（贵）
2. **二分查找**多次（便宜）

例子：AI 搜索引擎把文档按相关性排序，然后在前 K 个里二分搜。同样招——你查词典找 "warrior"。

## 三、在同一问题上跑四个算法（10 分钟）

```python
import time

def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1

def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

def in_list(arr, target):
    '''Python's built-in `in` operator.'''
    return target in arr

def set_lookup(s, target):
    '''Convert to set, then lookup.'''
    return target in s

# Make 10000-element sorted list
N = 10000
sorted_arr = list(range(N))   # 0, 1, 2, ..., 9999
s = set(sorted_arr)            # set version
# Worst case (last element)
target = N - 1

# Time each
for name, fn in [('Linear', linear_search), ('Binary', binary_search),
                 ('in_list', in_list), ('set_lookup', set_lookup)]:
    start = time.time()
    result = fn(sorted_arr if 'set' not in name else s, target)
    elapsed = time.time() - start
    print(f'{name:10s}: {elapsed:.6f}s  found={result}')
```

跑一下。惊喜：**集合查找最快**（哈希，O(1)）。二分紧随其后。顺序最慢。

## 五、深入了解：AI 工程师怎么用 Big O（3 分钟）

**AI 工程师的工作日常**：
- **选模型**：Transformer vs RNN vs LSTM——每种有不同 Big O
- **选搜索算法**：二分 vs 哈希 vs 向量搜索
- **选数据结构**：数组 vs 链表 vs 树 vs 图
- **选优化方法**：梯度下降 vs 牛顿法——前者 O(n)，后者 O(n²)

**真实案例**：
- **2017 年 Transformer 论文**：把 O(n²) 的 RNN 换成 O(n log n) 的注意力机制，**让大模型训练成为可能**
- **2020 年向量搜索**：把 O(n) 的搜索换成 O(log n) 的近似最近邻，**让 ChatGPT 实时响应成为可能**

**没学 Big O 的 AI 工程师 = 没学过刹车的赛车手**——飞出去是迟早的事。

## 六、何时用：选算法 4 步法（3 分钟）

1. **问 N 多大**？N < 100 随便选；N > 10000 选对算法
2. **数据排好序了吗**？没排，排序一次（贵），然后二分（便宜）
3. **查一次还是反复查**？反复查：建索引 / 哈希表
4. **量一下**：`time.time()` 包你的函数，跑 N=100, 10000, 1000000，看时间

**永远先量，再优化**。猜 = 浪费时间。
