## 二、先想后写：今天的任务是画图（3 分钟）

新手最常见的翻车：上来就敲代码，敲到一半发现房间连不上。职业做法是「**先想后写**」——先画清地图，代码只是把图翻译成 Python。今天全在纸上完成，不建游戏文件。

## 三、地图长什么样（2 分钟）

每张地图 = **房间**（方块）+ **连线**（能走的路）。一张 6 房间示例：

```text
[ 神社 Shrine ] —— 起点，玩家从这里出发
   |         \
[ 树林 Forest ]   [ 河边 RiverBank ]
  狼敌人          草药道具
                    |
              [ 独木桥 Bridge ]
                    |
              [ 巨鹰巢穴 BossNest ] —— 终点，打败巨鹰通关
```

**规矩：没有线的房间，玩家走不到。** 画图时每条线都要双向考虑——从 A 能去 B，那从 B 也得能回 A。

## 四、五个关键设计问题（2 分钟）

拿着笔，边画边答：

1. **几个房间？** 5-7 个最适合（多于 10 难维护，少于 4 没探索感）
2. **起点在哪？** 一个入口
3. **终点在哪？** 一个 Boss 房，打赢通关
4. **有没有岔路？** 1-2 个刚好，多了迷路
5. **敌人 / 道具放哪？** 标在方块旁边

## 五、从一个房间想到一堆数据（1 分钟）

写代码之前先学会「看图说话」：站在神社，玩家能做什么？

- 看到自己的位置 → 一个变量 `room`
- 选方向走 → `input` + `if` 判断
- 换房间 → 给 `room` 换一个新值

看到没有——**房间 = 一个 if 分支，方向 = 一个 if 条件**。这就是明天 S2 骨架的全部秘密。

**今日口诀：** 先想后写，房间是分支，连线是 if。

## 👀 C++ 认脸时刻（1 分钟 · 只看不敲）

C++ 的对应写法：

```cpp
#include <iostream>
// 先想：需要什么数据？函数？类？
// 画地图：房间数据 + 玩家位置 + 移动函数
struct Room {
    std::string name;
    int x, y;
};
int main() { return 0; }
```

三个认脸：

1. C++ `struct` 类似 Python dataclass
2. `std::string` 字符串类型
3. 先想数据 + 函数 = 设计
