## 二、三步走（5 分钟）

跟 W05 猜数字一样，分三块：

```python
def guess_number(low, high):
    '''Each step cuts in half, guess the middle.'''
    mid = (low + high) // 2
    print(f'I guess: {mid}')
    return mid

def update_range(low, high, mid, answer):
    '''Narrow range based on computer's answer -- W05 pattern.'''
    if answer == 'smaller':
        return mid + 1, high      # answer < mid, eliminate mid and below
    elif answer == 'bigger':
        return low, mid - 1       # answer > mid, eliminate mid and above
    else:  # hit
        return mid, mid

def main():
    low, high = 1, 100
    while low <= high:
        mid = guess_number(low, high)
        answer = input('bigger / smaller / hit? ').strip()
        if answer == 'hit':
            break
        low, high = update_range(low, high, mid, answer)
    print('Found it!')

main()
```

## 四、为什么"砍中间"？（3 分钟）

W06-S1 说砍一半——但砍哪儿？三种选择：

| 策略 | 例子 | 速度 |
|---|---|---|
| 永远砍第一个 | low 不动，high 移动 | 顺序查找（W07 会对比） |
| 永远砍中间 | `mid = (low + high) // 2` | **二分查找（今天）** |
| 随机砍 | 没规律 | 不可预期 |

**中间 = 平衡**。砍完两边差不多大。最坏情况 = 平衡树深度 = log₂(N)。

> **📖 图 3.1**：中间 = 平衡 = 砍完两边差不多大。这是二分为什么"快"的核心。

## 五、`//` 整除：要中间但不要小数（2 分钟）

`(low + high) // 2`：
- low=1, high=100：`(1+100) // 2 = 50`
- low=50, high=100：`(50+100) // 2 = 75`

为什么用 `//` 不用 `/`？Python 的 `/` 给出小数：`101/2 = 50.5`。做列表下标会报错。`//` 永远整数：`101//2 = 50`。

## 六、深入了解：二分查找为什么老出错（3 分钟）

Donald Knuth（《计算机程序设计艺术》作者）说过："二分查找看似简单，实则陷阱重重"。

**常见 bug**：
1. `while low < high`（漏 `=`）—— 漏掉 low == high 的情况
2. `high = mid`（漏 `-1`）—— 多查一次
3. `mid = (low + high) / 2`（用 `/`）—— 整数被算成小数

**多测边界**：
- 空列表（`len = 0`）
- 单元素（`len = 1`）
- 目标在第一个
- 目标在最后一个
- 目标不存在

**2006 年 Java 标准库的二分查找 bug 潜伏了快十年**。你的代码也几乎肯定会有 bug——**写完多测**。

## 七、何时用：二分查找的 4 个变种（3 分钟）

| 场景 | 变种 | 代码差异 |
|---|---|---|
| 找目标 | 标准二分 | 找到就 return |
| 找第一次出现 | 下界 | 不停往左缩 |
| 找最后一次出现 | 上界 | 不停往右缩 |
| 找"插入位置" | 二分插入 | 找不到就返回 mid |

W06-S4 的词典查找就是标准版。W06-S5 的"选对算法"会用上界。
